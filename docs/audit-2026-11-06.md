# Security review and Claude Desktop bundle — 2026-11-06

Scope: application source, OAuth callbacks and storage, tool responses, dependency
lockfile, repository history, packaging and GitHub Actions. This is a code and
automated-check review, not a penetration test or a guarantee of absence of flaws.

## Findings addressed in 0.3.1

| Finding | Resolution |
| --- | --- |
| `pip-audit` reported CVE-2026-49272 in locked oauthlib 4.0.0 | Upgrade to 4.0.1 and require at least 4.0.1 in project metadata. The affected device-code provider flow is not implemented by this application. |
| SDK exception strings and Google error descriptions could expose credentials or untrusted text through MCP | Return fixed messages for library exceptions, preserve only locally constructed validation messages and Google protobuf error codes/request IDs. Do not reflect callback error descriptions. |
| Settings dataclass representation included secrets | Exclude developer token, client secret and refresh token from `repr`. Invalid boolean configuration no longer echoes the value. |
| Manual OAuth helpers allowed arbitrary redirect destinations | Require HTTP loopback redirects for manual and automatic desktop flows. Existing non-loopback manual configurations must migrate. Prefer the local PKCE flow. |
| Browser callback responses could be cached | Add `Cache-Control: no-store` and `Referrer-Policy: no-referrer` on completed/error callbacks. |
| Build actions used mutable version references | Pin GitHub Actions to commit SHAs, uv and MCPB CLI to versions, and the gitleaks binary to its SHA-256 digest. |
| No native Claude Desktop installation bundle | Add a macOS MCPB 0.4 UV bundle with sensitive configuration fields, the full lockfile, explicit file allowlist and deterministic archive/checksum generation. |
| No release dependency audit or Mac bundle gate | Audit the lockfile on CI/release; release only after Mac bundle initialization and all ten tool schemas are verified. |

## Verification

- 81 tests passed locally on Python 3.13. Regression tests cover OAuth PKCE/state/expiry, private atomic token storage,
  both Google protobuf modes, safe error responses and packaging exclusions.
- Gitleaks scanned all 18 pre-release commits without detecting secrets.
- After the OAuthLib update, `pip-audit` reported no known vulnerabilities for
  locked runtime dependencies applicable to the local Python 3.13 environment.
  CI additionally audits its Python matrix; advisory results can change over time.
- Bandit findings were manually reviewed: four B105 heuristic matches on public
  endpoint/config/status strings, and one B310 `urlopen` warning. The production
  request uses the fixed HTTPS Google token endpoint, never a caller-supplied URL.
- The MCPB manifest is validated with the official `@anthropic-ai/mcpb` CLI 2.1.2.
- The bundle smoke test extracts the built artifact into a fresh directory with
  spaces in its path, runs its exact manifest launcher, checks ten tools and six
  read-only keyword annotations, and exercises missing-credential handling.
- Release workflow results are available in the repository's Actions tab. The
  downloadable artifact is the one built and smoke-tested by the Mac release job.

## Remaining boundaries

- Google Ads access is read-only in application code; the required Google
  `adwords` OAuth scope itself is broader. Tokens must still be treated as sensitive.
- Browser-generated refresh tokens are stored in a local plaintext file with
  `0600` permissions, not in Keychain. Same-user software can access them. Claude
  manages the manifest's sensitive configuration fields separately.
- Manual authorization-code exchange remains available for compatibility and
  does not provide the state/PKCE protections of the recommended browser callback.
- No live Google Ads request, interactive Google consent, or installation through
  Claude's graphical settings was performed during this review. Protocol startup
  tests do not verify account access or every Claude Desktop version.
- Requires current Claude Desktop with MCPB 0.4 UV support and network access on
  first launch. Dependencies are installed from the included lockfile. The package
  is not code-signed or reviewed by Anthropic. SHA-256 detects download differences
  but does not independently authenticate the publisher.
